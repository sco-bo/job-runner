# Job Puller — Product Spec

## Overview

A local Python CLI + lightweight web UI that runs daily to scrape job postings, score them against your profile, and surface the top 20 roles you're most likely to get. Resumes are stored locally as versioned files; your profile is a structured YAML you maintain. No cloud dependencies by default.

---

## Goals

1. Fetch fresh job postings daily from major boards (LinkedIn, Indeed, Glassdoor, etc.) and curated sources (Tangerine Feed)
2. Score and rank postings against your skills, experience, and target criteria
3. Deduplicate across runs so you don't see the same job twice
4. Match each job against a single skills bank to surface the best bullets and summary variant for that role
5. Output a ranked daily digest (top 20) as both a terminal summary and a browsable HTML report

---

## Non-Goals (v1)

- Applying to jobs automatically
- Integrating with ATS systems
- Multi-user support
- Cloud deployment

## Scoring Logic

Scoring happens in `scorer.py` using pure Python keyword heuristics. No API calls, no external dependencies beyond PyYAML. Produces a 0–100 value and a short rationale string per job.

Weighted components:
- **Title match** (30pts): Does the job title match your `target_titles` in `profile.yaml`?
- **Skills overlap** (30pts): Tokenize the job description and check for matches against (a) bullet `themes` tags and (b) raw bullet `text` in `skills_bank.yaml`. Score proportional to number of distinct matching themes.
- **Seniority match** (20pts): Does the level (senior/staff/lead/director) align with `target_levels` in `profile.yaml`?
- **Salary fit** (10pts): Is posted salary within `target_salary_min`/`max`? Full points if no salary listed (don't penalize missing data).
- **Location/remote** (10pts): Matches `preferred_remote` and/or `preferred_locations` in `profile.yaml`?

`avoid_keywords` in `profile.yaml` act as a multiplier: any match applies a 0.5× penalty to the final score.

`ranker.py` filters the scored job list before selecting the top 20:
- Jobs with `status = "dismissed"` are excluded entirely and never appear in ranked output
- Jobs with `status = "applied"` are excluded from the top 20 ranking pool and surfaced separately (see HTML Digest Report)

## Profile Schema (`profile/profile.yaml`)

Search preferences and scoring parameters. Does not contain resume content — that lives entirely in `skills_bank.yaml`.

```yaml
name: "Your Name"
target_titles:
  - "Senior Product Manager"
  - "Director of Product"
target_levels:
  - senior
  - director
  - lead
years_experience: 8
target_salary_min: 180000
target_salary_max: 280000
preferred_remote: true
preferred_locations:
  - "San Francisco, CA"
  - "New York, NY"
preferred_company_size:   # optional: startup, mid, large
  - startup
  - mid
avoid_keywords:           # applies 0.5x score penalty if found in job description
  - "10+ years required"
  - "must be on-site"
```

## Skills Bank (`profile/skills_bank.yaml`)

The single source of truth for all resume content. This file is written and maintained by the user — the tool never generates, parses, or modifies it from raw resume files. See full schema in the next section.

## Resume Matching (`resume_matcher.py`)

`resume_matcher.py` operates entirely in pure Python using stdlib + PyYAML. No API calls.

**Input:** job description text + `skills_bank.yaml`

**Algorithm:**
1. Tokenize the job description into a lowercase word set (strip punctuation, remove stopwords)
2. For each bullet in `skills_bank.yaml`, compute a match score:
   - +2 per theme tag that appears as a token in the job description
   - +1 per distinct word from the bullet's `text` that appears in the job description
   - Multiply by strength weight: `high` = 1.0, `medium` = 0.75, `supporting` = 0.5
3. Rank all bullets by score descending; return the top 8–10
4. Select the best `summary_variant` by counting theme overlaps: the theme whose keywords most overlap with the job description tokens wins

**Output** (stored in `matched_bullet_ids` and `recommended_summary` in the `jobs` table):
- List of top bullet `id` slugs (8–10)
- Best `summary_variant` label (e.g., `"data"`, `"customer"`)

## Skills Bank Schema (`profile/skills_bank.yaml`)

```yaml
name: "Your Name"
email: "you@example.com"
location: "Remote, US"
linkedin: "https://linkedin.com/in/yourhandle"

# 2–3 sentence summaries keyed by theme.
# Themes represent the angle you want to lead with for a given role.
summary_variants:
  data: "Summary emphasizing data platform experience..."
  customer: "Summary emphasizing customer-facing product work..."
  technical: "Summary emphasizing technical depth and eng partnerships..."
  growth: "Summary emphasizing growth, funnel, and experimentation work..."

education:
  - degree: "B.S. Computer Science"
    school: "University of Michigan"
    year: 2012

certifications:
  - "AWS Certified Solutions Architect"
  - "Pragmatic Marketing Certified"

bullets:
  - id: snowflake-etl-pipeline
    text: "Designed and shipped a self-serve ETL pipeline on Snowflake, reducing analyst query time by 60%"
    themes: [data, technical, self-serve, analytics]
    strength: high

  - id: b2b-onboarding-funnel
    text: "Rebuilt B2B onboarding funnel, improving 30-day activation by 22% across enterprise segment"
    themes: [customer, growth, fintech]
    strength: high

  - id: api-developer-platform
    text: "Led API-first developer platform initiative, growing third-party integrations from 12 to 80+"
    themes: [technical, api, developer-platform, growth]
    strength: medium
```

**Controlled theme vocabulary:** `data`, `technical`, `api`, `growth`, `customer`, `compliance`, `fintech`, `self-serve`, `analytics`, `leadership`, `startup`, `developer-platform`

**Strength values:** `high` (lead bullets), `medium` (supporting evidence), `supporting` (context/filler — used only if needed to reach 8–10)

## CLI Interface

```bash
# Run the full daily pipeline
job-puller run

# Run and open the HTML report when done
job-puller run --open

# Edit your profile (opens in $EDITOR)
job-puller profile edit

# View the skills bank (opens in $EDITOR)
job-puller profile skills

# Show today's top 20 without re-scraping (excludes dismissed/applied; shows applied count as footer line)
job-puller digest

# Show all jobs in DB matching a query
job-puller search "machine learning"

# Mark a job as applied/dismissed
job-puller job <url-or-id> --status applied
job-puller job <url-or-id> --status dismissed

# Print a ready-to-paste Claude.ai prompt for resume tailoring (no API calls)
job-puller tailor <job-id>
```

### `job-puller tailor <job-id>`

Fetches the job from SQLite, runs `resume_matcher.py`, and prints a fully formed prompt to stdout. The user copies this and pastes it into Claude.ai manually — the tool has no part in that exchange and makes zero API calls.

Prompt includes:
- Full job title, company, and description
- The recommended `summary_variant` text from `skills_bank.yaml`
- The top 8–10 matched bullets with full text
- An instruction block asking Claude to tailor the bullets and summary to the specific role

Example output:
```
=== TAILOR PROMPT — copy and paste into Claude.ai ===

I'm applying for: Senior Product Manager, Data Platform at Acme Corp.

JOB DESCRIPTION:
[full text]

MY RECOMMENDED SUMMARY:
[summary_variants.data text]

MY TOP MATCHED BULLETS:
- Designed and shipped a self-serve ETL pipeline on Snowflake...
- ...

Please help me tailor these bullets and summary for this specific role.
Focus on the data platform and self-serve themes. Keep bullets concise
and achievement-oriented. Do not invent metrics I haven't provided.
=====================================================
```

## HTML Digest Report

Generated at `reports/YYYY-MM-DD.html`. Each report shows:
- Run metadata (date, jobs fetched, new jobs found)
- **Top 20 ranked jobs** (excludes dismissed and applied) as cards with:
  - Score badge (color-coded)
  - Title, company, location, salary range
  - Remote flag
  - Score rationale (1–2 lines)
  - Recommended summary variant label (e.g., `data`, `customer`)
  - Top 3 matched bullet teasers: first 12 words of each bullet + ellipsis
  - Callout block showing the exact CLI command to run: `job-puller tailor <id>`
  - Link to original posting
- **Applied section** (below the ranked list): muted cards with an "Applied ✓" badge for all jobs with `status = "applied"`. Same card fields as above minus score rationale and tailor callout. Does not count toward the top 20.
- Dismissed jobs are never rendered anywhere in the report
- Footer with full database stats (total jobs, new today, applied count, dismissed count)

## Build Phases

### Phase 1 — Scrape + Store
- `scraper.py` wraps JobSpy, writes raw jobs to SQLite
- `tangerine.py` scrapes Tangerine Feed remote US PM jobs, writes to same SQLite schema
- Both scrapers feed into the same `jobs` table; `site` column distinguishes source
- CLI: `job-puller run` executes both scrapers
- Verify deduplication works across runs and across sources

### Phase 2 — Score + Rank
- `scorer.py` with keyword heuristics
- `ranker.py` picks top 20
- CLI: `job-puller digest` prints ranked table to terminal

### Phase 3 — Resume Matching + HTML Report
- `resume_matcher.py` matches job keywords to bullet themes/text in `skills_bank.yaml`
- Stores top bullet IDs and recommended summary variant in the `jobs` table
- `reporter.py` generates HTML digest with bullet teasers and tailor command callout
- CLI: `--open` flag to launch in browser

### Phase 4 — Profile CLI + Tailor Command
- `job-puller profile edit` and `job-puller profile skills` subcommands
- `job-puller tailor <job-id>` prints assembled prompt to stdout (no API calls)
- Validate both `profile.yaml` and `skills_bank.yaml` on load with clear error messages

## Tangerine Feed Scraper (`tangerine.py`)

### Source
- Base URL: `https://tangerinefeed.net/remote/product-manager-jobs/region/US`
- Pagination: `?page=N&sort=recent` (currently ~31 pages, ~303 jobs)
- robots.txt: `Allow: /` — AI crawlers explicitly welcomed

### Approach
Each page embeds a `<script type="application/ld+json">` block containing a `schema.org/ItemList`. Parse this directly rather than scraping raw HTML — it's more reliable and less likely to break on layout changes.

JSON-LD fields available per job:
- `title`
- `hiringOrganization.name` (company)
- `url` (direct job link — used as dedup key)
- `datePosted`
- `jobLocationType` (always `TELECOMMUTE` for this endpoint)

Additional fields (salary, description, skills) require following each job's detail URL. Fetch detail pages only for jobs that pass a basic title/recency filter to avoid unnecessary requests.

### Pagination strategy
1. Fetch page 1, sorted by `recent`
2. For each job on the page, check `datePosted` from the JSON-LD against a 24-hour cutoff
3. Fetch detail page only for jobs within the cutoff
4. Stop paginating as soon as an entire page contains no jobs within the 24-hour window

### Rate limiting
Add a configurable `tangerine_delay_seconds: 1` in `config.yaml` between page requests. The site welcomes crawlers but no need to hammer it.

### Config additions (`config.yaml`)
```yaml
tangerine:
  enabled: true
  base_url: https://tangerinefeed.net/remote/product-manager-jobs/region/US
  sort: recent          # recent | salary | pto | parental
  hours_old: 24         # only fetch detail pages for jobs posted within this window; stop paginating once a page is all older
  fetch_details: true   # follow each job URL to get full description + salary (only for jobs within hours_old)
  delay_seconds: 1      # pause between requests
```

## Open Questions (to resolve during build)

1. **LinkedIn rate limits** — JobSpy may get blocked without proxies on LinkedIn. May need to start with Indeed/Glassdoor only and add LinkedIn with a proxy config later.
2. **Profile bootstrapping** — Resolved: if `profile.yaml` or `skills_bank.yaml` are missing when any command runs, the tool exits immediately with a descriptive error naming the missing file and pointing to the template (e.g., `Error: profile/skills_bank.yaml not found. Copy profile/skills_bank.template.yaml to get started.`). No interactive prompting.
4. **Dismissed/applied tracking** — Resolved: dismissed jobs are excluded from all output permanently. Applied jobs are excluded from the top 20 ranking pool but appear in a separate "Applied" section in the HTML digest; the terminal `digest` command shows a count only.
5. **Tangerine detail fetching** — Resolved: only fetch detail pages for jobs posted within the last 24 hours. The JSON-LD `datePosted` field on the listing page is sufficient to filter before following any detail URLs. Stop paginating once all jobs on a page are older than 24 hours.
